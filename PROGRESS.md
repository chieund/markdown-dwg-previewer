## 📊 Performance

Real measurements from `npm run test:corpus` on 17 AutoCAD sample drawings.

| Step | DWG path | DXF path |
|------|-----------|-----------|
| Read + convert | 14 – 562 ms | 0 – 13 ms (no conversion needed) |
| Parse | 5 – 6,812 ms | 5 – 1,499 ms |
| Render first paint | ~200 ms | ~200 ms |
| Full render (progressive) | ~1.5 s for large files | same as DWG |
| Reopen unchanged file | ~0 ms (cache by path + mtime) | ~0 ms |

Heaviest file in the corpus — `colorwh.dwg`, 1.7 MB → DXF 9.2 MB → 36,431 entities:
convert 562 ms, parse 6.8 s. The same content loaded directly from `.dxf` takes only 1.5 s to parse,
because it skips both the conversion step and the memory pressure the WASM creates.

**6.8 s for 36K entities is an anomaly** — a real-world 45K-entity drawing takes only 640 ms.
Most likely because this file is HATCH-heavy. Added to the backlog.

### 🐛 Corpus finding: 3D drawings open blank with no explanation

4 `visualization_*` files render almost nothing (`aerial` and `sun_and_sky_demo` yield **0
entities**, `conference_room` 8, `condominium` 6). Inspecting their ENTITIES section:

| File | Actual content |
|------|---------------|
| `visualization_-_aerial` | 5 × 3DSOLID, 1 × PLANESURFACE |
| `visualization_-_sun_and_sky_demo` | 15 × 3DSOLID, 2 × VIEWPORT |
| `visualization_-_conference_room` | 30 × 3DSOLID, 6 × LIGHT, 6 × INSERT, 4 × LWPOLYLINE… |

These are 3D drawings, so a 2D extension can't render them — that's acceptable. **The problem is elsewhere:
`skippedEntityTypes` is empty**, so the toolbar warning banner shows nothing. The user opens the file and
sees a blank canvas with no explanation whatsoever.

Cause: `parseDxf.ts:1024` only records skipped entities **inside `mapEntity`**, and
`mapEntity` only sees what dxf-parser managed to read. dxf-parser silently drops
3DSOLID / PLANESURFACE / LIGHT up front, so they never reach the counter.

**Half-fixed in v1.0.3:** the empty state now shows a message explaining the empty canvas, so
users no longer stare at a silent black screen. But since `skippedEntityTypes` is still empty,
the message only says generically that "the drawing is built from 3D solids/meshes/surfaces" and **cannot name
the actual entity types** in the file. The toolbar banner still shows nothing either.

To fully fix it, the parser needs to count entity types from the DXF text itself and compare them with what was mapped
— only then can both the banner and the empty state name them correctly. Still in the backlog, priority High.

## 🔗 Syncing fixes from the `markdown-dxf-previewer` project

The two projects share most of `src/dxf/`, so fixes made there must be ported here.

**Ported — mirrored INSERTs drawn at the wrong position and angle** (source: commit `f879b0d`, 08/11)

AutoCAD's MIRROR command usually doesn't touch the block geometry; instead it flips the INSERT's
extrusion direction to `(0,0,-1)`. The insertion point (codes 10/20) and rotation (code 50) are then stored in the
flipped OCS, not world coordinates — reading them directly misplaces every mirrored block.

Fix: `extrusionMatrix()` in `src/dxf/matrix.ts` (DXF's arbitrary axis algorithm),
multiplied as the outermost transform in the `expandInsert` chain.

Why it slipped through every earlier check: **the 17 AutoCAD sample files contain no mirrored
INSERTs**, so the corpus test could never hit it. Only real architectural drawings use MIRROR heavily.

Verification: disabling the fix → tests go red; before/after screenshots of Real-world drawing B
show strokes outside the drawing frame dropping from 64 px and 61 px to **0**.

**Not yet reviewed:** other commits in the DXF project (`3eb0b06`, `bd179a3`) touch `parseDxf.ts`,
`viewport.ts`, `renderer.ts`, `export.ts` — not yet compared to see whether any other differences are worth porting.

## 🔍 Code review & fix round 2 (2026-10-06 → 10-07, branch `fix/review-findings`)

Full review of `master`: 0 Critical, 14 Important. All fixed; for #14 (license) the project owner chose to open-source the code → GPL-3.0-or-later.
An independent reviewer then re-reviewed the fixes themselves and caught 2 bugs introduced by the fixes — also fixed.

| # | Issue | Fix |
|---|--------|----------|
| 1 | OCS ignored for every entity except INSERT → mirrored ARC/CIRCLE/polyline/TEXT/HATCH end up on the wrong side | Apply `extrusionMatrix` to the OCS-based types; dxf-parser doesn't expose 210 for CIRCLE/TEXT, so scan the raw text by handle (`src/dxf/extras.ts`). Mirrored text is counter-rotated + its alignment swapped so it stays readable; hatch pattern angles are mirrored accordingly |
| 2 | Geometry on layer 0 inside a block took layer 0's color instead of the INSERT's layer | `resolveColor` uses the resolved layer |
| 3 | DXF R12–R2004 read as UTF-8 → Japanese text becomes `�`; MTEXT lost `\S1/2;`, `\U+`, text after `\L` | `src/dwg/encoding.ts` reads `$DWGCODEPAGE` (valid UTF-8 takes precedence); rewrote MTEXT as a tokenizer; `\U+`, `\M+n` (Shift-JIS…) |
| 4 | Multi-line MTEXT collapsed into 1 line | One `<tspan>` per line, vertical alignment by attachment |
| 5 | SOLID hatch drawn over text | Restore hatches to file order by handle — single-pass merge (first version was O(n²): 20k hatches took 68 s) |
| 6 | SVG export had a transparent background (`%` rect computed from the origin) | Rect covers the viewBox |
| 7 | 211-byte file (INSERT 1000×1000) → 1 million entities; 32767² → OOM kills the whole extension host | 500k entity cap + warning banner; **convert + parse run in `worker_threads`** (`src/dwg/worker.ts`) with a 3 GB heap cap — OOM only kills the worker, the next job spins up a new one |
| 8 | Every viewport copied the whole model | Filter by view frame **at collect time** (doesn't consume the entity budget); text bounding boxes respect alignment |
| 9 | `parseCache` never evicted | LRU of 4 drawings; 2 panels on the same file share one conversion and both receive progress |
| 10 | **Security:** `converterPath` could be set from an untrusted repo's `.vscode/settings.json` → arbitrary binary execution | `scope: machine` + declare `untrustedWorkspaces: limited` |
| 11 | Showed frozen/off layers, hidden ATTRIBs, invisible entities | Drop `60=1` entities and ATTRIBs with the invisible flag; layer-off flags trusted only for native `.dxf` files (see below) |
| 12 | Live reload lost zoom/page/layers; half-written files showed an error | 300 ms debounce, generation token discards stale results, view state preserved, reload errors only show a banner |
| 13 | Docs overpromised | Fixed README/MARKETPLACE |
| — | Viewport ignored the view target (17/27) → `blocks_and_tables_-_metric` had 1 blank viewport | View center = target + view center |
| — | Toggling 1 layer rebuilt the whole SVG | `src/webview/layerIndex.ts`: draw everything once, toggle only changes `display` |
| — | Minor | Aligned/Fit alignment, per-style font (code 7), EXPORT message validation, WASM promise caching (retry on load failure), `\N`, half-empty stack |

**Key findings from running the corpus:**
- **libredwg writes a negative color (= layer off) for EVERY layer** in all 17 files → the layer-off flag is only used for native `.dxf`
  (`parseDxf(text, { trustLayerOffFlags })`). Additionally, if hiding by flag would leave the first page completely empty, everything is shown.
- **The entity count drop in 5 files is correct:** dynamic blocks store every visibility state, and inactive states carry `60=1`
  — previously 4 door styles / 4 title block sizes were drawn on top of each other; `blocks_and_tables` has 413 hidden ATTRIBs. Each
  number was cross-checked and verified with screenshots.
- **libredwg/AutoCAD write viewport status `68=0` for every inactive layout** — it must not be interpreted as "viewport off"
  (the first fix misinterpreted it and blanked the layouts of `plot_screening…`, `colorwh`; the second reviewer caught it).
- The corpus now also counts entities inside viewports (`viewportEntities`) — the bug above slipped through precisely because they weren't counted before.

### Major directions worth considering

**Drop the intermediate DXF text round-trip.** `@mlightcad/libredwg-web` already exposes `dwg_read_data()` +
`convert()`, which return a structured `DwgDatabase` directly (36 entity types defined, including HATCH /
VIEWPORT / ATTRIB / LEADER / MULTILEADER / TABLE). The pipeline currently goes
`DWG → 18 MB DXF string → 7 scan passes`. Using `convert()` would eliminate the intermediate string, remove
about 700 lines of hand-written raw scanners, and open the way for currently unsupported entities.

Needs a spike comparing entity counts before starting — the corpus baseline is the safety net.

### 2026-08-12 — 15:55 · v1.0.3 · UI/UX improvements + mirrored INSERT fix

**Bug fix — mirrored INSERTs drawn at the wrong position and angle**

AutoCAD's MIRROR command usually doesn't touch the block geometry; instead it flips the INSERT's
extrusion direction to `(0,0,-1)`; the insertion point and rotation are then stored in the flipped OCS
rather than world coordinates. Reading them directly misplaces every mirrored block.

- Ported `extrusionMatrix()` (DXF's arbitrary axis algorithm) from the
  `markdown-dxf-previewer` project — commit `f879b0d`, where the bug was fixed on 08/11
- Real-world impact: Real-world drawing B has **29/152 INSERTs** mirrored,
  Real-world drawing A has 4/304
- The 17 AutoCAD sample files have **no** mirrored INSERTs — so the corpus test could not
  detect this bug, which is why it slipped through every earlier check
- Verified with before/after screenshots: strokes outside the drawing frame dropped from 64 px and
  61 px to 0

**UI/UX improvements**
- **Empty state** — an empty canvas now always states the reason; fixes the P0 bug the corpus test found (3D drawings opening pitch black without a word of explanation)
- **Status bar** — coordinates, zoom level, object count, interaction hints (addresses the fact that double-click = fit was previously undiscoverable)
